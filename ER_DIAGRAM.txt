╔════════════════════════════════════════════════════════════════════════════╗
║                              LEGEND                                        ║
╠════════════════════════════════════════════════════════════════════════════╣
║                                                                            ║
║  PK   = Primary Key                                                        ║
║  FK   = Foreign Key                                                        ║
║  UQ   = Unique Constraint                                                  ║
║  1:N  = One-to-Many Relationship                                           ║
║  M:N  = Many-to-Many Relationship                                          ║
║  ──►  = Foreign Key Reference                                              ║
║                                                                            ║
╚════════════════════════════════════════════════════════════════════════════╝


╔════════════════════════════════════════════════════════════════════════════╗
║                         RELATIONSHIP SUMMARY                               ║
╠════════════════════════════════════════════════════════════════════════════╣
║                                                                            ║
║  ONE-TO-MANY RELATIONSHIPS:                                                ║
║  ────────────────────────────────────────────────────────────────────────  ║
║  1. Users        → Incidents   (one user can be assigned many incidents)  ║
║  2. Users        → Comments    (one user can author many comments)        ║
║  3. Users        → Activities  (one user can perform many activities)     ║
║  4. Incidents    → Cases       (one incident can have many cases)         ║
║  5. Incidents    → Comments    (one incident can have many comments)      ║
║  6. Cases        → Comments    (one case can have many comments)          ║
║  7. Cases        → Activities  (one case can have many activities)        ║
║                                                                            ║
║  MANY-TO-MANY RELATIONSHIPS:                                               ║
║  ────────────────────────────────────────────────────────────────────────  ║
║  1. Cases ↔ Users   (via case_assignments)                                ║
║     - One case can have multiple assigned analysts                        ║
║     - One analyst can be assigned to multiple cases                       ║
║                                                                            ║
║  2. Cases ↔ Alerts  (via case_alerts)                                     ║
║     - One case can contain multiple alerts                                ║
║     - One alert can be part of multiple cases                             ║
║                                                                            ║
╚════════════════════════════════════════════════════════════════════════════╝


╔════════════════════════════════════════════════════════════════════════════╗
║                         CASCADE DELETE RULES                               ║
╠════════════════════════════════════════════════════════════════════════════╣
║                                                                            ║
║  When INCIDENT is deleted:                                                 ║
║  → All related CASES are deleted (CASCADE)                                 ║
║  → All related COMMENTS are deleted (CASCADE)                              ║
║                                                                            ║
║  When CASE is deleted:                                                     ║
║  → All related COMMENTS are deleted (CASCADE)                              ║
║  → All related ACTIVITIES are deleted (CASCADE)                            ║
║  → All entries in CASE_ASSIGNMENTS are deleted                             ║
║  → All entries in CASE_ALERTS are deleted                                  ║
║                                                                            ║
║  When USER is deleted:                                                     ║
║  → Assigned incidents remain (assigned_to_id set to NULL)                 ║
║  → Comments and activities remain (referential integrity)                 ║
║                                                                            ║
╚════════════════════════════════════════════════════════════════════════════╝


╔════════════════════════════════════════════════════════════════════════════╗
║                          INDEX STRATEGY                                    ║
╠════════════════════════════════════════════════════════════════════════════╣
║                                                                            ║
║  HEAVILY INDEXED FIELDS (for performance):                                 ║
║  ────────────────────────────────────────────────────────────────────────  ║
║  • Foreign Keys         - All FK columns indexed                           ║
║  • Status Fields        - incident.status, case.status, alert.status      ║
║  • Severity/Priority    - For filtering critical items                     ║
║  • Timestamps           - For time-based queries                           ║
║  • IP Addresses         - For threat hunting (src_ip, dst_ip)             ║
║  • Hostname/Agent       - For asset-based queries                          ║
║  • Category/Event Type  - For alert classification                         ║
║  • Username             - For user activity tracking                       ║
║                                                                            ║
║  UNIQUE CONSTRAINTS:                                                       ║
║  ────────────────────────────────────────────────────────────────────────  ║
║  • users.username       - Prevent duplicate usernames                      ║
║  • users.email          - Prevent duplicate emails                         ║
║  • alerts.source_id     - Prevent duplicate alert ingestion                ║

║         │   │   └─► Not Found: Create new INCIDENT                         ║
║         │   │                                                              ║

║             ├─► Analyst reviews ALERTS in CASE                             ║
║             ├─► Adds COMMENTS with findings                                ║
║             ├─► ACTIVITIES logged automatically                            ║
║             └─► Updates CASE status → RESOLVED                             ║
║                 │                                                          ║
